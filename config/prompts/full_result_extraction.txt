You are extracting benchmark results from the WHOLE text of a graph learning paper.

The paper text may be long. Return a COMPACT JSON object ONLY. Never return a top-level array.
No markdown fences, no prose explanation.

Compact output schema:
{
  "proposed_model_name": "<exact main model name or null>",
  "proposed_model_type": "<gnn|graph_transformer|hybrid|llm|walk|svm_kernel|random_forest|decision_tree|boosting|other_traditional|null>",
  "proposed_params_millions": <float or null>,
  "baseline_model_names": ["<baseline name>", "..."],
  "baseline_model_types": {"<baseline name>": "<model_type or null>", ...},
  "baseline_params_millions": {"<baseline name>": <float or null>, ...},
  "results": [
    {
      "m": "<exact model name>",
      "p": <true|false>,
      "d": "<dataset>",
      "k": "<metric>",
      "v": <float>,
      "s": <float or null>,
      "h": <true|false>,
      "e": <true|false|null>,

      "q": "<node_classification|node_regression|graph_classification|graph_regression|link_prediction|other>",

Rules:
- Protocol decision (mandatory for EVERY row): use `u=standard` only when the focused table,
  caption, and nearby experiment paragraphs support the canonical task and standard split.
  Use `u=nonstandard` only for clear evidence of another task or non-comparable protocol, and
  `u=uncertain` when evidence is incomplete. Set `z=true`, false, or null accordingly.
- Do not treat unrelated mentions elsewhere in the paper as evidence against the current table.
- `coverage_assessment` is complete only when all relevant result tables were reviewed.
- Extract ONLY main benchmark comparison results on standard datasets.
- Do NOT extract ablations, component removals, hyperparameter sweeps, sensitivity studies,
  runtime-only tables, or appendix-only diagnostics. Skip tables whose captions identify them
  as ablation or diagnostic.
- Most papers have one main model, sometimes two or more distinct proposed methods. Mark `p=true`
  for each main proposed method. When several rows are variants of the same method name family,
  output one row per (that method, dataset, metric) with the best score — not one row total per
  dataset.
- Do NOT mark all tuned or starred baseline variants as proposed.
- Copy model and dataset names verbatim from the paper when possible.
- Use test-set benchmark values only.
- Match the experiment task to the canonical dataset task supplied in the user context. For
  example, do not report Cora/PubMed link-prediction AUC/AP tables as node-classification
  results just because the dataset names are familiar. If the paper only evaluates a different
  task, return an empty `results` list and explain the mismatch briefly in `notes`.
- If you are unsure whether a row is proposed, set `p=false`.
- If a field is unknown, use null or an empty list/string as appropriate.
- Never output a bare list. Always output the compact object.
- model_type values: gnn, graph_transformer, hybrid, llm, svm_kernel, random_forest,
  decision_tree, boosting, other_traditional, or null. Use llm when a language model is the
  core model on graphs (not just external pretraining). Classify from explicit paper statements.
- params_millions: only when explicitly stated in this paper for that exact model; else null.
- uses_external_data (`e`, per row): true if that model uses pretraining/fine-tuning on data
  outside the benchmark train split (external graphs, LLM/PLM features, transferred weights, etc.).
  false if only benchmark training data is used (including PEs computed on the same graph).
  null when unclear for that specific model row. Flag each row independently.
- input feature source (`f`, per row): identify the features consumed by the reported model.
  Use `llm_features` for features produced by or initialized with an LM/LLM/PLM/SLM, including
  BERT, DeBERTa, TAPE, SimTeG, GIANT-XRT, and LLM-generated text or annotations. Use
  `raw_features` for dataset-provided features and ordinary non-LM representations such as
  bag-of-words, TF-IDF, GloVe, word2vec, and standard positional encodings. Use
  `other_external_features`, `mixed`, or `unknown` as appropriate. Read table group headers and
  nearby setup prose; the same displayed model may have different feature sources in different
  rows, so preserve those rows as separate variants.
