You are helping extract benchmark results from a research paper.

Given a TARGET DATASET and a numbered list of source tables with their captions, role evidence,
and column headers, identify which tables contain numeric benchmark results for that dataset.
The source table numbers are authoritative and must not be renumbered.

INCLUDE a table if it:
- Reports model performance scores on the target dataset (by name or common abbreviation)
- Compares multiple models on a benchmark that includes the target dataset

DATASET NAME RESOLUTION:
- Dataset labels in tables are sometimes abbreviated, truncated, punctuated, or shortened
  (for example, "Cham." can mean "Chameleon"). Match such labels to the full dataset names
  appearing elsewhere in the paper, including dataset descriptions, captions, headers, and
  surrounding experiment prose. Do not reject a relevant table solely because it lacks the
  exact full target-dataset string.
- Use the exact target dataset name from the input as the key in your output; do not invent a
  separate dataset for an abbreviation that clearly refers to it.

Appendix benchmark tables are first-class sources and may contain the paper's complete or
summarized results. Do not exclude or deprioritize a table merely because it is in the appendix.

EXCLUDE a table if it:
- Is statistics-only (size, splits, number of graphs/nodes) and contains no model scores
- Lists hyperparameters or training configurations
- Shows run times or compute costs
- Reports results exclusively for other, unrelated datasets
- Is an ablation, sensitivity, component-removal, hyperparameter, or diagnostic table, even if it
  reports scores on the target dataset
- Shows results for optional variants or alternative configurations of the dataset
  (e.g., different graph construction formats, SLIC values, resolution variants)
  when a main results table already covers the standard configuration

Output a JSON object ONLY — no markdown fences or prose outside the JSON object:
{"relevant_table_numbers": [<integer>, ...], "explanation": "<why any selected table without a dataset-name match is correct>"}

The supplied deterministic dataset-match block is a conservative constraint. Prefer tables with
an exact or fuzzy dataset-name match. A selected table without such a match is allowed only when
the explanation is non-empty and states why the table is nevertheless the correct result table.

Mixed tables are allowed: if a table contains both dataset statistics and model scores, select it
when it contains benchmark results for the target dataset. Use the result-bearing cells only.

If genuinely unsure between a main benchmark table and an ablation/diagnostic table, keep only the
main benchmark table.
Return an empty list ONLY if you are certain no table contains results for the target dataset.
