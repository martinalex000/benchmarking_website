LaTeX table re-extraction — server runbook
==========================================

Use this after deploying wraptable / sidewaystable parser fixes, or when
refreshing papers flagged on Development → Problematic Papers.

Prerequisites
-------------
- Repo updated on the server (includes backend/latex_source.py table-env fix).
- papers/<arxiv_id>/latex/expanded.tex already present (normal download step).
- LLM workers configured (.env, vLLM or external endpoint).

Step 1 — Scan local LaTeX for problematic table coverage
----------------------------------------------------------
From the repository root:

  uv run python scripts/scan_latex_table_issues.py --write-list --export-json

This writes:
  - site/data/problematic_latex_papers.json  (development page input)
  - config/reextract_latex_papers.txt        (re-extraction ID list)

Optional: limit to one paper while debugging:

  uv run python scripts/scan_latex_table_issues.py --paper 2411.05274 --write-list --export-json

Step 2 — Publish the development page (optional but recommended)
----------------------------------------------------------------
Regenerate Hugo data + dev pages so “Problematic Papers” is visible:

  uv run python -m backend.export_to_hugo
  cd site && hugo

Step 3 — Mark papers for LLM re-extraction in todo_papers
---------------------------------------------------------
Either mark directly during the scan:

  uv run python scripts/scan_latex_table_issues.py --mark --requeue --write-list --export-json

Or mark from the saved list file:

  uv run python scripts/mark_reextract_papers.py mark --requeue

--requeue resets done/failed/rejected todo rows back to pending.

Step 4 — Remove stale extraction artifacts (recommended)
----------------------------------------------------------
Workers skip extraction when llm_output already exists unless --force is used.
For a clean re-run, delete main outputs for flagged papers, e.g.:

  while read -r line; do
    id="${line%%#*}"
    id="$(echo "$id" | xargs)"
    [[ "$id" =~ ^[0-9]{4}\.[0-9] ]] || continue
    rm -f "papers/$id/extracted/llm_output.json" \
          "papers/$id/extracted/llm_output.yaml"
  done < config/reextract_latex_papers.txt

Keep papers/<id>/latex/ and PDF/HTML downloads — only re-extract.

Step 5 — Re-run extraction with --force
-----------------------------------------
Single paper smoke test:

  uv run python scripts/run_manual.py 2411.05274 --skip-download --force

Parallel queue (important papers first):

  uv run python scripts/todo_queue_dashboard.py --workers 10 --model primary --force

Or continuous workers:

  while true; do
    uv run python scripts/todo_queue.py worker --model primary --important-only --force \
      >> logs/reextract_worker.log 2>&1 || break
  done

Step 6 — Re-export the site
---------------------------
After workers finish:

  uv run python -m backend.export_to_hugo
  cd site && hugo

Notes
-----
- “Re-parse only” (no new LLM calls) is NOT sufficient here — these papers need
  full model re-execution because table discovery/RAG changed.
- Anchor regression paper: 2411.05274 (DRAGON / LRGB wraptable peptides).
- Development page: /dev/problematic-papers/ after export.
