## Why The Counts Can Differ

There are two different counting paths in the website:

1. Landing page (`/`): counts come from generated benchmark data (`site/data/benchmarks.json`).
2. Dataset overview (`/datasets/`): counts come from exported dataset pages in `site/content/datasets/*`.

Because these paths aggregate differently, the landing page can show larger numbers.

## What Is Included In Each Count

### Landing page counts (`site/data/benchmarks.json`)

Generated by `uv run python -m backend.export_to_hugo` in `backend/export_to_hugo.py` (`export_benchmarks_data`).

- Uses raw DB result row counts per dataset.
- Excludes rows marked problematic (`is_problematic = 1`).
- Does not apply the dataset-page dedup logic used for leaderboard rows.

### Dataset overview counts (`site/content/datasets/*/index.md`)

Generated by `backend/export_to_hugo.py` (`export_dataset`).

- Uses dataset page rows after export-time cleanup.
- Deduplicates shared repeated baselines reported across papers.
- Applies dataset-level metric display filters from `config/dataset_overrides.yaml`.
- Only includes datasets that successfully export a page.

## Interpreting A Difference

If landing-page numbers are larger, this is typically one (or more) of:

- Raw DB rows include repeated shared baseline reports across papers.
- Some datasets exist in benchmark data but do not currently export a dataset page.
- Dataset-level display filtering hides non-selected metric columns on dataset pages.

For presentation and user-facing leaderboard totals, the dataset-overview values are usually the safer source of truth.

## Where To Inspect

- Export logic: `backend/export_to_hugo.py`
- Benchmark aggregate data: `site/data/benchmarks.json`
- Rendered dataset pages: `site/content/datasets/*/index.md`
- Dataset display filters: `config/dataset_overrides.yaml`
